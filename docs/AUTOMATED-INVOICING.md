# Automated SIJATIM invoicing

SIJATIM retains the existing Laravel authentication and red styling. The invoice month is distinct from usage: AGU26 bills July 1–31 and SEP26 bills August 1–31. January invoices use December of the preceding year.

## Operator workflow

The operator works through three screens per period. Expert tools are on a separate **Menu Lanjutan** page.

1. **Layanan & Downtime.** In an empty period, choose **Salin dari tagihan bulan lalu** (copies the latest issued service state) or **Ambil semua SSID aktif dari Master**. Every SSID starts as **Existing**. Search, or use the filter chips (Ada perubahan, Ada downtime, Downtime belum diisi, Terjadwal bulan depan).
   - **Relokasi** has no effective date. It flags the SSID for this invoice month (billed as a full month; relocation fee from the tariff, currently 0) and the new address is entered in the **next** invoice month: there the SSID shows "Relokasi bulan lalu: alamat baru belum diisi" with **Isi alamat baru**, a filter and a banner, and a blocking checklist item until the address is saved. The address is stored on the period line and in the master SSID list. Imported relocation rows may omit the date.
   - Lines whose old draft type order (e.g. Relokasi) has no recorded change show "Draf lama" with **Catat perubahan** or **Tandai Existing**.
   - **Ubah Layanan** records Upgrade, Downgrade, Relokasi, or Cabut. Upgrade, Downgrade and Cabut need an effective date. A date inside the usage month applies to this invoice. A later date (up to 12 months ahead) is saved as a scheduled change and applied automatically when the period for that usage month is created or receives the SSID. Cancelling a change requires a reason.
   - **Downtime** takes one integer number of seconds for the usage month. The screen shows the value in days/hours/minutes and the maximum active seconds. **Upload downtime (Excel)** uses the two-column template (`SSID`, `Downtime (detik)`). After preview and **Terapkan** it returns to this screen. A service may have only one downtime value. If a file row collides with downtime already recorded for the same SSID, the preview shows a red **Bentrok** box listing both values, with the choices **Pakai nilai dari file** and **Pertahankan yang sudah ada** (per SSID, or for all at once); **Terapkan** stays disabled until every collision is decided. Entering a manual number over a value that came from a file requires ticking **Ganti nilai dari file**. If an SSID already has several competing records, it shows **Bentrok** on this screen and **Pilih nilai** opens a list to keep one (or type a new number). The records not chosen are marked "tidak dihitung", never deleted, and withdrawing a replacing file restores the earlier value.
   - **+ SSID baru (PSB)** registers a new SSID in the master if needed, adds it to the period, and records the installation. A future date schedules it.
   - **Konfirmasi N SSID lainnya tanpa downtime** records zero downtime only for SSIDs that have no downtime yet.
   - A PSB or Cabut shortens the billable window. A confirmed **0 detik** follows the new window automatically. A downtime with seconds is kept but marked **Isi ulang** (it also appears under the "Downtime belum diisi / perlu diisi ulang" chip) until the operator saves it again.
   - The invoice number and dates are edited with **Ubah info invoice**. Customer and supplier data come from Master Harga › Data Pelanggan & Invoice.
2. **Periksa & Hitung.** Click **Hitung Invoice**. The page lists what must be completed before issuing, in plain language, each with a link to the screen that fixes it (missing tariffs → Master Harga, missing downtime → step 1, unfinished uploads → Menu Lanjutan). It then shows Subtotal, PPN, and Total, a collapsible breakdown, and a per-SSID table with SLA and credits.
3. **Terbitkan.** **Finalisasi & buat file** (with confirmation) locks the period and queues Excel and PDF generation. The page refreshes itself until the files are ready, then offers the downloads (Excel, PDF and a **summary picture**). The picture (`Ringkasan_<kode>_v<n>.png`, 1416 px wide) follows the layout of the Telkom SUMMARY sheet: A–F by order type, G–J SLA and restitution, total after restitution, PPN, grand total. It is drawn from the frozen snapshot, so it always agrees with the Excel (whose Summary sheet uses the same figures) and PDF, and it is previewed on this page. A failure to draw it never blocks the invoice documents; **Buat gambar ringkasan (PNG)** creates it for versions issued before the feature existed or when it is missing. G counts services whose actual SLA is known and not below the 99% target; H counts those below it. A failed generation can be retried. **Buka revisi** (requires a reason) reopens a locked period; earlier files remain downloadable.

**Menu Lanjutan** holds all import kinds (workbook, inventory, tariffs, MRTG, incidents, adjustments, notes), source history, outage review (dihitung / tidak dihitung / menunggu), interval coverage declarations, manual credits and tariff overrides, full invoice details, branch totals, the complete issue list, differences from the previous issued invoice, and recent activity.

**Master Harga** has tabs for Tarif, Daftar SSID, Data Pelanggan & Invoice (versioned billing profile), and Kontrak. Forms show essential fields first and the rest under "Opsi lain". The change note is optional; every save is still recorded in `billing_audit_events`. Bulk price lists can be loaded with `php artisan db:seed --class=BankJatimTariffSeeder` (Tabel 1 tanpa router and Tabel 2 dengan managed router; effective 2025-01-01, PSB 1.981.982, relocation 0). It is idempotent, never overwrites an existing price (it reports differences) and reports rows whose category, service or bandwidth is missing from the master. Managed-router tariffs apply only to SSIDs whose **Router ditagih** is set to managed. To correct starting bandwidths from an operator list, run `php artisan billing:fix-bandwidth AGU26 path/to/list.csv` (CSV with `;`, `,` or tab, or XLSX; columns SSID and bandwidth; `0` means TIDAK BERLAKU). It only previews until `--apply` is added, then updates the period and the master SSID list, records an audit event, and requires **Hitung ulang**. Any unknown SSID, duplicate or unknown bandwidth stops it without saving. Installation and relocation fees accept explicit zero. The tariff register matches location category, service, bandwidth, router mode, contract if selected, SID applicability, and effective dates. A tariff without a location category ("Semua kategori") is a general price per service/bandwidth/router, such as the Non Mikrotik list used after an upgrade or downgrade; the most specific tariff wins: SID-specific, then the service's category, then the general price. An empty bandwidth on a tariff means TIDAK BERLAKU (no bandwidth), not any bandwidth. Ambiguous matches at the same level block issuance.

**PPN.** The Tarif tab of Master Harga (the page the sidebar link opens) shows the current PPN as a percentage, "PPN: 11%", with an **Ubah** button. The operator types a percentage from 0 to 100 (decimal comma or point, e.g. `11` or `11,5`); it is stored as the multiplier in the billing profile's `tax_rate` (11 -> `0.11`) as a new profile version, and recorded in `billing_audit_events` (`admin_ppn_saved`) with the optional change note. The same value is the field "PPN (%)" under Opsi lain of the Data Pelanggan & Invoice form (the multiplier is still accepted as `tax_rate` by the endpoint). **A change applies to every period that is not locked:** each switches to the new profile version and its calculation becomes stale (`master_ppn_updated` audit event, same `markInputsChanged` mechanism as other Master changes), so **Hitung Invoice** must be clicked again before issuing. **Issued invoices never change:** a locked period keeps its profile version, and an issued revision keeps its frozen snapshot and files, which still carry the rate they were issued with. The Excel "PPN 11%" label and the Step 2 PPN card read the rate from the snapshot; the tax itself is `round(subtotal x rate)`. Percent formatting ("11%", "11,5%") and parsing are in `App\Services\Billing\TaxRate`. The price-list screen (`price-masters/index`, currently without a route) takes its "+ PPN n%" headers and PPN-inclusive amounts from the configured rate instead of the stored `*_with_ppn` columns.

Preview pages and dashboard reads do not recalculate or save inputs. The legacy invoice download URL serves the latest successful Excel revision. Historical snapshot invoices are retained.

## Initial profile

SLA target is fixed at 0.99 (99%) for every SID and cannot be changed through billing profiles or service inputs. Actual SLA is calculated from reviewed downtime and the SSID's active billable seconds; unconfirmed downtime remains unknown. Proration uses a fixed billing month of 30 days (February 28, also in leap years); calendar day 31 (and 29 February) is not billed. Daily tariff = monthly price / 30 (February / 28), rounded half up to whole rupiah; a segment covering all billing days is billed flat at the monthly price. Billing days of a segment = min(end day, 30 or 28) - start day + 1. A PSB is billed from the day after its date (PSB 1 Aug = 29 days, PSB 30 or 31 Aug = 0 days; installation fee unchanged); a master "Awal ditagih" date counts from its own day. A Cabut bills the cut day itself (Cabut 21 Aug = 21 days, 31 Aug = full month). An upgrade/downgrade on day d bills the old rate for days 1..d-1 and the new rate from d (15 Aug = 14 + 16 days). Each rate segment in the snapshot records its `billing_days` and `month_days`. The profile's proration divisor is no longer used by the calculation. SLA and downtime keep real calendar seconds of the active window (a PSB window still starts on the PSB date). Monetary calculations to two decimals; subtotal rounded once to whole rupiah; tax multiplier from the billing profile (`tax_rate`, 0.11 = 11% unless changed under **PPN** above) with tax rounded to whole rupiah. The subtotal rounding difference is shown separately. No blanket router surcharge is applied.

The output workbook (`Invoice_<kode>_v<n>.xlsx`) has exactly three sheets, in this order:

- **Harga** lists the price of each service from Master Harga (title "DAFTAR HARGA LAYANAN – <bulan>", header on row 3): one row per active tariff that is valid in the invoice's usage period. Columns: Kategori lokasi ("Semua kategori" for a general price), Layanan, Bandwidth, Router (Tanpa router / Dengan router), Harga bulanan, Biaya instalasi, Biaya relokasi, SID khusus, Mulai berlaku, Berlaku sampai, Kontrak. Rows are sorted by layanan, kategori ("Semua kategori" first), bandwidth (by speed) and router. The list comes from the tariffs stored in the calculation snapshot, so a file issued again matches what was calculated even if Master Harga has changed since; Master Harga is read only for an older snapshot that holds no tariff list.
- **Detail Layanan** follows the customer's Telkom MONTHLY RECURRING CHARGES sheet: header rows 3–4, column letters with a filter on row 5, one row per SSID from row 6. Columns A–AG: No, Jenis kantor, Alamat, Kategori lokasi, Layanan, Type order (EKSISTING / PSB / RELOKASI / UPGRADE / DOWNGRADE / CABUT, or the changes joined with " + "), ID (SID), Period (invoice month yyyymm), Bandwidth eksisting / upgrade / downgrade, IP host, Tanggal aktivasi, Tanggal mulai aktif upgrade/downgrade, Pemakaian average (Kbps), Traffik total (GB, the system's volume), Durasi downtime (detik), SLA actual, SLA PKS, Availability (detik), Restitusi over SLA, Restitusi tagihan, Harga eksisting / upgrade / downgrade / cabut / PSB / relokasi, Total, Harga setelah restitusi and Sub total per cabang (on the first row of each branch). Below the SSID rows one TOTAL row carries the snapshot totals. Panes are frozen at D6.
- **Summary Invoice** follows the customer's SUMMARY sheet and carries the same figures as the summary picture, built from the same function (`SummaryImage::rows()`), so the two always agree: title "INVOICE PERIODE <BULAN>", then the lines A to F by order type, the total, G to J (SLA met and not met, restitusi SLA, restitusi tagihan), the total after restitution, PPN and the grand total. It is the sheet that opens first.

The PPN label ("PPN 11%") is derived from the tax rate in the snapshot (0.11 when the snapshot has none), so a later change of the PPN setting flows through; it is not typed into the sheet. Amounts are numeric cells formatted `#,##0` (restitusi and the per-SSID total keep two decimals so the cents of an SLA credit stay visible, and Excel shows the separators of the viewer's regional settings), dates are real dates (dd/mm/yyyy) and SSIDs are stored as text so leading zeros and dashes survive. The detail of the former thirteen-sheet layout that is not part of these three sheets (imported source rows, outage tickets, MRTG recap, notes) stays in the frozen snapshot. All exports use typed values from the frozen revision and contain no copied formulas or external links; before a version is marked ready the generator checks the sheet names and order, that the Detail Layanan net total (and the sum of its SSID rows) and the Summary Invoice grand total equal the snapshot, and that there are no formulas or external links. PDF uses local fonts and A3 landscape tables, repeated headers, and page numbers.

## Runtime and worker

The installed PHP runtime is 8.5. PhpSpreadsheet is a direct dependency; the unused Maatwebsite integration was removed to support this runtime. Dompdf uses its direct API with the required `^3.1` constraint. Composer's lockfile is authoritative for supported runtime versions.

Run migrations and build assets before serving the application:

```powershell
php artisan migrate --force
npm run build
php -d memory_limit=1024M artisan queue:work database --queue=default --sleep=1 --tries=3 --timeout=300 --memory=1024
```

**Automatic worker.** By default (`BILLING_AUTO_WORKER=true`, `config/billing.php`) the application starts a one-shot background `queue:work --stop-when-empty` itself when documents are waiting: right after **Finalisasi** or **Coba buat file lagi**, and whenever the Terbitkan page (or its 5-second status poll) sees a locked period still waiting for its files. Running only `php artisan serve` is therefore enough on a single machine. The job also raises its own memory limit to `BILLING_WORKER_MEMORY_MB` (default 1024), so it works with any way of starting a worker. `composer dev` runs the server, a `queue:listen` worker and Vite together (Pail was removed: it needs the `pcntl` extension, which Windows lacks). On a server, set `BILLING_AUTO_WORKER=false` and keep a supervised worker running instead. Keep a supervised database queue worker running in that case. Generation uses a 300-second job timeout and a 360-second reservation interval. Use a PHP memory limit of 1024 MB for full monthly workbooks and PDF generation: with 775 services generation takes about 25–35 seconds and peaks near 630 MB, and with PHP's default 128 MB it fails while writing the Excel file. Without a running worker, **Finalisasi** locks the period but the files are never created (the revision stays "approved" and a job waits in the `jobs` table); on Windows double-click `start-queue-worker.bat` and leave its window open.  Configure upload size limits consistently with the application's 25 MB limit. Source files, draft previews, and outputs are private under `storage/app/private/billing`. Only authenticated download routes expose issued documents.

## Reconciliation and draft previews

Inspect a reference workbook against a period without committing anything:

```powershell
php -d memory_limit=512M artisan billing:reconcile AGU26 "path/to/august.xlsx" --output=storage/logs/reconciliation-august.json
php -d memory_limit=512M artisan billing:reconcile SEP26 "path/to/september.xlsx" --output=storage/logs/reconciliation-september.json
```

Generate clearly marked draft documents for layout inspection, without creating invoices or modifying calculations:

```powershell
php -d memory_limit=768M artisan billing:preview-documents AGU26
```

The supplied references contain inconsistencies and cannot be treated as unconditional expected totals. August contains competing calculation/printable credit totals and ticket date issues. September contains a new SID, a tariff discrepancy, and July MRTG data copied into the August usage invoice. The adapters flag these conditions; an operator must resolve sources and eligibility before routine issuance.

The initial read-only reconciliation reports are `storage/logs/reconciliation-august.json` and `storage/logs/reconciliation-september.json`. They detected 775 and 776 inventory records, respectively; August had 36 rows needing normalization or master matching, while September had 802, including its 775 wrong-period traffic records. These counts describe import issues, not a completed billing approval. No reference file was committed and no current draft was issued by these checks.

Normalized templates use SID text, ISO dates `YYYY-MM-DD`, timestamps `YYYY-MM-DD HH:mm:ss`, and decimal points. Indonesian grouped currency values are explicitly parsed. Ambiguous raw dates or amounts require correction. Numeric zero is preserved. Traffic averages are decimal Kbps; volume is decimal GB only with full-window coverage. Imported document text is data and is never executed as formulas or instructions.

## Migration and recovery

The pre-migration SQLite backup is `C:/Users/epeto/.codex/backups/sijatim/20261009-124508/database.sqlite`. Original draft row values are stored in `invoice_lines.legacy_inputs`; existing AGU26/SEP26 drafts were shifted to the preceding usage month, with old SLA and defaulted event dates invalidated. They were not finalized.

Billing migrations are forward-only because issued snapshots are immutable. To roll back this initial rollout, stop the application and worker, preserve newly generated artifacts and database changes, and restore the backup deliberately. Do not run a destructive rollback against issued invoice history.

## Verification

Run `php artisan test` and `npm run build`. Billing tests cover calendar transitions, reference proration, credit signs, unknown and overlapping outages, exact seconds, decimals and zero, staged commit failure, import idempotency, shifted XLSX tables, unexecuted formula text, router pricing, multiple events, stable recalculation, withdrawn sources, partial traffic coverage, live readiness, revision immutability, locked mutation routes, read-only previews, document reconciliation, and failed-worker retry. A separate test launches two concurrent finalizations against an isolated SQLite database and verifies one invoice, one revision, and one queue job. Test fixtures use isolated databases and private fake storage; they do not issue the current drafts. Six existing optional API-token tests are skipped when that Jetstream feature is disabled.

The rollout checks passed 26 active tests with 160 assertions, the production asset build, view compilation, PHP syntax checks, Composer validation and platform requirements. The 775-service draft export was inspected on PDF pages 1, 22, and 43 for repeated headers, long addresses, readable currency and unclipped totals. Its Excel workbook (thirteen sheets at that time; now the three sheets Harga, Detail Layanan and Summary Invoice) was checked for typed SIDs, visible service rows, absence of formulas and absence of external links. Retrying an older failed revision was also verified to leave a newer draft editable.

Live monitoring, payment tracking, scheduled issuance, and separate reviewer approval are outside this version.
